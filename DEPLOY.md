# Deploy a public demo

A demo for presentations, free of charge: the API and its PostgreSQL database on
[Render](https://render.com), the web app on [Vercel](https://vercel.com). The
browser only talks to the web app, which forwards `/api` to the API, so there is
no CORS to set up.

```
Browser ──> Vercel (web/, Next.js) ──/api──> Render (backend/, Django) ──> Render PostgreSQL
```

## 1. API and database on Render

1. Sign up at https://dashboard.render.com with GitHub, and allow it to see this repository.
2. **New** > **Blueprint**, pick the repository, branch `main`. Render reads `render.yaml`.
3. **Apply**. It creates `vidyalaya-db` (PostgreSQL 16) and `vidyalaya-api`. The first deploy takes 5 to 10 minutes.
4. When `vidyalaya-api` shows **Live**, copy its address from the top of its page, for example `https://vidyalaya-api.onrender.com`.
   Open `<address>/api/config` in a browser: you should see JSON with `"demo"` filled in.

Each start runs `bin/start.sh`: `migrate`, a check that the database role is subject to row-level security, `seed_demo` and gunicorn.

## 2. Web app on Vercel

1. Sign up at https://vercel.com with GitHub.
2. **Add New** > **Project**, import the repository.
3. **Root Directory**: `web`. The framework is detected as Next.js.
4. **Environment Variables**: `API_URL` = the Render address from step 1.4, no trailing slash.
5. **Deploy**. Your demo is at the `https://<project>.vercel.app` address Vercel shows.

`API_URL` is read when the web app is built. If it changes, redeploy on Vercel.

## 3. Optional: invite links

Invite links in emails point at `WEB_APP_URL`. To demo inviting someone, add
`WEB_APP_URL` = your Vercel address under `vidyalaya-api` > **Environment**.
No email is sent: the message, with its link, is in `vidyalaya-api` > **Logs**.

## Demo logins

The sign-in page has a button for each role. Every password is `Demo-pass-2026`.

| Role | Email |
|---|---|
| Platform owner | owner@demo.test |
| School admin | admin@greenvalley.test |
| Teacher | teacher@greenvalley.test |
| Student | student1@greenvalley.test |
| Parent | parent1@greenvalley.test |

Parents can also choose **Parent code**. With `DEMO_MODE` on, the code for a demo
account (an address ending in `.test`) is shown on screen and filled in, because
no SMS is sent. Codes for any other address are never shown.

A second school, Riverside Academy, has the same accounts under `@riverside.test`.

## Before you present

- Render's free API sleeps after 15 minutes without visits and takes about a minute to wake. Open `<API address>/api/config` two minutes before you start.
- The free database is deleted 30 days after it is created. Make a new Blueprint for a later demo.
- Data people change during the demo stays. Each restart tops the demo data back up but does not undo changes.

## Settings

| Variable | Where | What |
|---|---|---|
| `DEMO_MODE` | API | `true` loads the demo data, shows the demo logins and shows demo parent codes. Never for a real school. |
| `DATABASE_URL` | API | Set by the Blueprint from `vidyalaya-db`. |
| `DJANGO_SECRET_KEY` | API | Generated by the Blueprint. |
| `DJANGO_DEBUG` | API | `false`. |
| `LOGIN_THROTTLE_RATE` | API | `60/min`, so a room of people can sign in at once. |
| `CSRF_TRUSTED_ORIGINS` | API | Only needed to use the Django admin through another domain. |
| `API_URL` | Web | The API's address. |

The database role must not be a superuser or have BYPASSRLS, or schools are not
kept apart. At every start `check_db_role` prints which it is, and a
warning in the Render logs if the role skips the policies.
